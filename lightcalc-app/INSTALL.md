# Установка ZimaLED LightCalc на сайт zima-led.ru

## Что нужно сделать

### 1. Залить папку `lightcalc-app/` на хостинг zima-led.ru
Скопировать всю папку `dist/` (переименовать в `lightcalc-app/`)
в корень сайта — так, чтобы работало:

    https://zima-led.ru/lightcalc-app/lightcalc.css
    https://zima-led.ru/lightcalc-app/assets/js/embed.js
    https://zima-led.ru/lightcalc-app/assets/data/catalog.json     ← аварийная копия

Через FTP это папка обычно называется `public_html/` или `www/`.

### 2. Вставить сниппет в HTML-виджет на странице /lightcalc

1. Войти в WebSite X5 (или CMS zima-led)
2. Открыть страницу «Калькуляция освещения» (URL `/lightcalc`)
3. Найти HTML-виджет с id `imHTMLObject_56_01`
   (тот, где сейчас текст «Здесь должен быть рабочий код…»)
4. Вставить туда содержимое файла **`embed-snippet.html`**
5. Опубликовать страницу.

### 3. Проверка
Открыть https://zima-led.ru/lightcalc — должен появиться мастер калькулятора
с фирменной палитрой zima-led. Пройти пресет «Кухня-гостиная» — убедиться,
что каталог zima-led загружается (список товаров с ценами).

## 🔄 Автоматическое обновление каталога

**Каталог обновляется автоматически.** Не нужно ничего перезаливать при
добавлении товара — калькулятор напрямую читает файл `/cart/x5cart.js`,
который WebSite X5 обновляет сам при каждом изменении товаров.

Как это работает:
1. При первой загрузке страницы `catalog-loader.js` делает `fetch /cart/x5cart.js`
2. Парсит объект `x5CartData.products`, фильтрует по нужным категориям
3. Сохраняет результат в `localStorage` браузера пользователя на **1 час**
4. При следующем заходе — если кэш свежий (<1 ч), берёт его; иначе — перезагружает

В шапке калькулятора есть **бейдж** справа:
- 🟢 «65 товаров · live» — только что загружено с сайта
- 💾 «65 товаров · 15 мин назад» — из кэша браузера
- ⚠️ «49 товаров (offline)» — использована аварийная копия `catalog.json`

**Клик по бейджу** принудительно обновляет каталог, минуя кэш.

Аварийная копия `assets/data/catalog.json` нужна на случай, если
`/cart/x5cart.js` временно недоступен (CDN, отзеркалирование и т.д.).
Её можно периодически обновлять, но это не критично — обычно живой файл
всегда доступен, ведь без него не работает и корзина сайта.

## 🏆 Витрина «Топ-12 проектов» + рейтинг звёздами (v2.0)

Под «Готовыми сценариями» (Шаг 1) появилась адаптивная витрина 12 самых
популярных проектов, которыми делились посетители: мини-план, смета
(считается движком), средняя оценка ★ и голосование 1–5.

Как это работает:
- «Ссылка на проект» теперь регистрирует шеринг в PHP-API (`api/share.php`)
  и отдаёт КОРОТКУЮ ссылку `…/lightcalc#s=ID` (36 Б). Если PHP-API недоступен —
  безотказный fallback `#p=…` (payload целиком в hash), как в v1.9.
- Голос: анонимный токен из localStorage (НЕ фингерпринт, НЕ сырые IP).
  Сервер хранит только хэш (токен + IP-хэш + соль). Повторный голос
  ИЗМЕНЯЕТ оценку. Лимит: 40 голосов/IP-хэш в сутки.
- Рейтинг топа — байесовское среднее (как у IMDB): одна пятёрка от друга
  не выстрелит проект в топ; в топ попадают проекты с ≥3 голосов,
  добивка по популярности (шеринги + открытия).
- Витрина появляется ТОЛЬКО если `api/probe.php` ответил корректно
  (runtime-самопроба, 2.5 с). Нет PHP — нет витрины, калькулятор работает
  как раньше. Нулевой риск.

Требования: PHP 7.1+ на хостинге (обычно уже включён), права на запись
на `lightcalc-app/api/data/` (775). Никаких изменений в CMS/виджете.

### Проверка после деплоя (1 минута)
Откройте `https://zima-led.ru/lightcalc-app/api/selftest.php` — все пункты
должны быть зелёными (сиды «Топ-12» импортируются автоматически при первом
запросе). Файл можно удалить после проверки.

### Стартовое наполнение (сиды)
12 реалистичных проектов зашиты в `api/seed/*.seed.json` (генератор:
`node scripts/make_seeds.mjs` — пересобирает сиды реальным движком калькулятора).
Чтобы сбросить статистику: удалите `api/data/shares.json` и `api/data/votes.json`
(при следующем запросе сиды импортируются заново).

## Обновление каталога товаров
Раз в неделю (или по расписанию) запустить `scraper/scrape_zima.py`
на любой машине с Python — он спарсит актуальные товары/цены с сайта
и обновит `assets/data/catalog.json`. Затем перезалить только этот файл.

## Скрипты сборки и обновления каталога (в репозитории, вне папки lightcalc-app/)

В корне репозитория живут два вспомогательных скрипта (их НЕ нужно заливать
на хостинг — на хостинг идёт только собранная папка `lightcalc-app/`):

    MainRepa/
    ├── scripts/
    │   └── build_embed.py        # сборка dist/ из исходников lightcalc-app/
    └── scraper/
        └── scrape_zima.py        # обновление аварийной копии catalog.json

`build_embed.py` проставляет версию `?v=YYYYMMDD-uiN` в JS-импортах и в
сниппетах, копирует/скопит CSS и собирает `dist/`. `scrape_zima.py`
переиспользует логику `catalog-loader.js` через Node, поэтому результат
не расходится с рантаймом калькулятора.

## Отладка

**Не видно калькулятор**
Открыть DevTools (F12) → Console. Обычно причина одна из:
- Неправильный BASE-путь (проверьте что `/lightcalc-app/lightcalc.css` открывается)
- Смешанный HTTP/HTTPS (все ресурсы должны быть по HTTPS)
- Кэш браузера (Ctrl+Shift+R)

**Стили сайта сломались**
Значит CSS не полностью scoped. Пришлите скриншот и HTML-снимок —
доработаем `prefix_css` в `scripts/build_embed.py`.

**Каталог пустой, «Нет моделей для этого напряжения»**
Значит `catalog.json` не загрузился. Проверьте:
- Абсолютный путь в browser DevTools → Network
- Content-Type: `application/json`

## Как обновлять сам калькулятор
1. Внести изменения в исходники в `assets/`
2. Запустить `python scripts/build_embed.py`
3. Перезалить содержимое `dist/` на хостинг
4. В сниппете в виджете БОЛЬШЕ ничего менять не нужно — версия JS/CSS
   привязана к query-параметру `?v=…`, обновляется автоматически.

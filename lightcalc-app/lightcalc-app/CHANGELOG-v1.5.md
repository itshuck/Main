# Обновление v1.5 — встраиваемые светильники: направленный свет вниз (не поворотный спот)

## Проблема
Встраиваемые светильники (роль «downlight_luminaire») ошибочно классифицировались как
поворотные споты (spot_gu10 / spot_gx53 / spot): у них появлялась ручка поворота на плане
и ползунок наклона в свойствах. Хотя это направленный свет — светится СТРОГО ВНИЗ,
без наклона и вращения.

## Что сделано
1. **cct.js**
   - добавлен тип пучка **`downlight_lens`** — встраиваемый направленный свет вниз
     (чёткий узкий пучок, directional=false).
   - `inferLuminaireType`: для встраиваемого светильника, у которого **НЕ указан поворот**
     (ни в характеристиках `Поворот H/V`, ни в описании/параметрах) — возвращается
     `downlight_lens` (узкий пучок ≤55°) или `downlight` (широкий), а НЕ spot_*.
   - `getRotationLimits`: для таких моделей `canRotateH=false`, `canRotateV=false` (0°).
   - хелпер `_hasExplicitRotation` — определяет, указан ли поворот. Если указан (>0) —
     модель считается поворотной (уважаем реальные данные).
2. **editor.js** — для фиксированного встраиваемого:
   - в свойствах не показываются ползунок наклона и пресеты (только «⬇ вниз (фиксированный)»);
   - на плане нет ручки вращения и линии-индикатора направления;
   - пятно принудительно светит вниз (90°), даже при сохранённом постороннем угле.
3. **render2d.js** — согласована визуализация итогового плана (`downlight_lens` добавлен,
   `_inferType` для встраиваемых → `downlight`*). Совпадает с редактором.

## Валидация
- `node --check` — чисто. Тесты **88/88** (добавлены регрессы: встраиваемые не поворотны и
  направлены вниз; узкий/широкий пучок → нужный тип; трековые споты ОСТАЮТСЯ поворотными).
- CSS scoped — не влияет на стили сайта.

## Файл
- Пакет: `lightcalc-app` (путь `/lightcalc-app/`), сниппет: `embed-snippet.html`.

# Обновление v1.8.1 — окончательный фикс сворачивания панелей на мобильном (ui12)

## Проблема (повторный отчёт)
Пользователь снова видит на мобильном в Редакторе плана незакрывающуюся правую
панель `#ed-right-panel` с маркером `.ed-panel-collapsed` («СВОЙСТВА ▶»),
занимающую ~50% экрана.

## Диагноз
Корень был в том, что JS-флаг `isMobile` определялся ТОЛЬКО через
`window.matchMedia(...)`. В ряде браузеров/webview `matches()` возвращает
неверное значение или вовсе недоступен, при этом CSS-медиа-запрос продолжает
применяться (bottom-sheet на <820px). Итог: JS думал «не мобильный» → рендерил
маркер свёрнутой панели, а CSS всё равно растягивал её как bottom-sheet на
половину экрана.

## Что сделано
1. **editor.js** — робастное определение мобильного вида: помимо `matchMedia`
   проверяется реальный размер окна (`innerWidth/innerHeight`):
   `isMobile = окно узкое ИЛИ matchMedia.matches`.
2. **editor.js** — редактор ставит явный класс `.collapsed` на сворачиваемую
   панель (`classList.toggle('collapsed', …)`) в `_renderLeftPanel`/
   `_renderRightPanel`.
3. **lightcalc.css** — в мобильном медиа-блоке добавлено жёсткое правило:
   `.editor-3dsmax .ed-panel.collapsed { display: none !important; }`.
   Оно прячет свёрнутую панель БЕЗУСЛОВНО, независимо от того, совпал ли
   `matchMedia`, есть ли пустой `:empty` и какие классы на `body`.

Эти три уровня защиты гарантируют: свёрнутая панель на мобильном никогда не
занимает экран. Открытие — через кнопки тулбара «＋ Каталог» / «＋ Свойства».

## Валидация
- `node --check` всех JS — чисто.
- CSS-правило `.ed-panel.collapsed{display:none!important}` подтверждено в
  мобильном медиа-блоке.
- `build_embed.py` воспроизводит пакет байт-в-байт (ui12).

# Обновление v1.9 — 100% надёжная ссылка на проект (ui13)

## Проблема
Кнопка «🔗 Ссылка на проект» (Шаг 5 «Результат расчёта») работала нестабильно:
одни ссылки открывались (200), другие — нет (404/400).

## Диагноз (подтверждён замерами)
Payload проекта+сцены кодировался в base64 и клался в **query-параметр** `?p=…`,
который отправляется на сервер вместе с запросом. Замеры длины URL:
- малый проект (7 светильников) — 2 588 симв. → сервер отвечал 200;
- средний (31 светильник) — **8 126 симв.** — на границе лимита
  nginx `large_client_header_buffers` (по умолчанию 4×8k);
- большой (62 светильника) — **15 828 симв.** — гарантированный 404/400
  от хостинга/CDN (Cloudflare, ModSecurity и т.п.).

Отсюда «иногда 200, иногда 404»: чем больше проект — тем длиннее URL.

## Решение (двухслойная гарантия)
1. **Payload перенесён в hash-фрагмент URL** (`…/lightcalc#p=…`).
   Фрагмент после «#» НИКОГДА не отправляется на сервер: сервер видит всё тот
   же запрос `/lightcalc` и отвечает 200 при ЛЮБОМ размере проекта.
   Класс ошибки «длинный URL → 404» устранён полностью.
2. **Компактный формат v3 + сжатие** — ссылка ещё и короткая (для мессенджеров):
   - компактная схема (позиционные массивы, ключи-инициалы, округление до мм);
   - сжатие `deflate-raw` через `CompressionStream` (все современные браузеры),
     fallback — несжатый v3 для старых;
   - **base64url** (без `+/=`) — ссылка не требует percent-кодирования и
     переживает копипаст в любой мессенджер;
   - префиксы формата: `3z.` (сжатый), `3.` (несжатый).

## Надёжность
- **Самопроверка при копировании**: кодируем → декодируем → сравниваем.
  Битая ссылка не попадёт пользователю (при сбое — явное сообщение).
- **Обратная совместимость**: старые ссылки `?p=…` (base64 JSON v2 и ранние
  варианты с encodeURIComponent) продолжают открываться — чтение идёт и из
  hash, и из query.
- **Безопасность не ослаблена**: развёрнутый v3-проходит ТЕ ЖЕ белые списки
  и клампы, что и раньше (`sanitizeSharedScene`, `sanitizeLightMix`,
  валидация зон/комнат/системы), лимит размера payload 400 КБ.
- Повреждённый/мусорный hash — мягкая деградация: чистый старт мастера,
  без падения приложения.

## Замеры после фикса
| Проект | Было (?p=) | Стало (#p=, v3+deflate) |
|---|---|---|
| Малый (7 свет.) | 2 588 | ~0.5 КБ |
| Средний (31 свет.) | 8 126 (404!) | **647** |
| Большой (62 свет.) | 15 828 (404!) | **858** (−95%) |

## Валидация (jsdom, реальный код приложения)
- Полный цикл: проект → saveLocalProject → реальный buildShareUrl → свежая
  страница с `#p=…` → восстановление: комната/зоны/система/сцена/BOM 31
  светильника совпали, смета идентична (91 365 ₽), шаг = редактор. **10/10**.
- Легаси `?p=` (v2, без сцены): проект восстановлен, авто-сцена построена. **9/9**
  (включая большой проект и мусорный hash).
- `node --check` всех JS — чисто; регрессия движка (auto 91 540 ₽ /
  scene 91 365 ₽, integrity.valid=true) — цифры совпадают с ui12.
- `build_embed.py` воспроизводит пакет байт-в-байт (ui13).

# Обновление v2.0 — витрина «🏆 Топ-12 проектов» + народный рейтинг звёздами (ui14)

## Идея
На основе безотказного шаринга (v1.9) — витрина 12 самых популярных проектов,
которыми делились посетители, с оценкой 1–5★. Размещена в Шаге 1, под блоком
«Готовые сценарии», в адаптивном контейнере.

## Состав
1. **PHP-API рейтинга** (`lightcalc-app/api/`, без БД — JSON + flock):
   - `probe.php` — самопроба: витрина появляется только если API жив

   - `share.php` — регистрация шеринга + выдача payload по ID → КОРОТКИЕ

     (m=3): одна пятёрка не выстрелит проект в топ; добивка по популярности;
   - `selftest.php` — пост-деплой проверка в браузере (1 минута).
2. **Кодек v3 вынесен в `share.js`** (переиспользуется генератором сидов),
   app.js импортирует его же — поведение шаринга v1.9 не изменилось.
3. **Витрина** (`app.js` + CSS): карточки с мини-планом SVG (комната/треки/
   светильники), сметой реальным движком, рангами 🥇🥈🥉, звёздами с hover,
   кнопкой «Открыть проект» (тот же путь валидации, что и ссылка).
4. **Сиды**: 12 стартовых проектов (`api/seed/`, генератор
